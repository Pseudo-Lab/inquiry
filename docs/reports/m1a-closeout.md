# M1a 실행 검증 마감

작성: 2026-09-15. 기준: REVIEW C-0a, PRODUCT-CONCEPT §7.

## 상태

**현재 구현·실행 검증 작업 마감. 최초 사용 UX의 최종 Exit 확인은 미실시로 남김.**
사용자 승인으로 M1b에 진행한다. REVIEW C-0b는 M1a와 독립 진행 가능하므로 이를 M1a의 무조건 통과로 해석하지 않는다. M2 전에는 두 마일스톤의 잔여 UX 판단을 정리해야 한다.

## 실행 결과

OpenAI `gpt-6-astra`로 5종 실제 실행. 모의 답변도 동일 모델이며, 아래 표는 실행 출력에 대한 에이전트 정성 평가다.

| 입력 | 비유도·3~5문항 | 중심 질문·판단 기준·범위 | 가설 다양성 |
|---|---|---|---|
| 연구 | 통과·3문항 | 통과 | 통과·3개 |
| 제품 | 통과·3문항 | 통과 | 통과·3개 |
| 정책 | 통과·4문항 | 통과 | 통과·3개 |
| 창작 | 통과·3문항 | 통과 | 통과·3개 |
| 사고실험 | 통과·3문항 | 통과 | 통과·4개 |

- 연구: 반복성·기존 방법의 한계·개선 평가 가능성으로 연구 선택을 구체화했다.
- 제품: 화면/로그를 함께 다루는 반복 업무에서 재사용·시간·수고 감소를 기준으로 삼았다.
- 정책: 시험 도입의 조건을 후속 1문항으로 확인하고 전면 도입과 구분했다.
- 창작: 글의 설명력과 소개할 방법의 실증 효과를 분리했다.
- 사고실험: 실용적 목적과 정량 실증을 강요하지 않고 설명 이후 남는 문제를 충분성으로 삼았다.

모두 8항목과 2~4개 `[suggested]` 후보를 생성했다. 테스트 11개는 API 경계·키 로딩·기존 답변 재개·질문 상한·2문항 조기 종료 회귀를 검증한다.

## 실제 사용자 피드백과 변경

사용자는 질문이 어렵고 반복되며, 검증 목적이 불명확하다고 피드백했다. 질문 표현을 일상어로 바꾸고, 진행자 종료 조건이 초점·쓰임·충분성을 확인하도록 조정했다. 기존 실제 3개 답변을 고정한 비교에서 수정 전 즉시 종료, 수정 후 초점·충분성 후속 2문항이 관찰됐다.

이후 기존 대화를 새 시드로 요약해 다시 시작하는 오류를 발견했다. `--history-file`로 실제 Q&A와 질문 수를 이어받고 질문의 이유·남은 최대 문항 수를 출력한다. 이미 5문항에 답했다면 추가 진행자 호출 없이 프레임을 만든다. 실제 사람 답변 5항목으로 추가 질문 0개를 확인했다.

대표 결과: [실제 사람 답변 프레임](m1a-human-frame.md).
이력의 질문은 쉽게 풀어 쓴 보조 질문을 포함하므로 처음부터 무보조로 진행한 5문항 검증이라고 보지 않는다. 초기 질문 이해도 실패는 자동 실행 성공으로 지우지 않는다.

## 유지할 한계

- 새 질문 안내를 사용자가 다시 체험한 UX 확인은 하지 않았다. 반복 검증 요청으로 사용자를 더 피로하게 만들지 않기로 했다.
- 5종 실행은 확률적 모델의 제한된 사례다. 반복 안정성의 통계적 보장은 아니다.
- 글의 충분성은 정성적·잠정적 기준으로 정리되며, 사용자가 소개한 해결법의 장기 효과를 입증한 것은 아니다.
- API 키는 프로젝트 `.env`에만 두며 Git에서 제외한다. 자동 이력 저장은 없다.
