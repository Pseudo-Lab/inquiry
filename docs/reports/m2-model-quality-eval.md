# M2 실제 모델 산출물 품질 평가 기록

2026-10-07. 지금까지의 모든 M2 검증은 fake adapter·합성 transport·사람이 작성한 fixture로 수행되어, **실제 모델이 생성한 내용의 품질은 전 보고서에서 "미검증"으로 남아 있었다**([m2-entry-check](m2-entry-check.md), [m2-3-framing-eval](m2-3-framing-eval.md), [m2-4a-openai-eval](m2-4a-openai-eval.md), [m2-4b-operations-eval](m2-4b-operations-eval.md)). 이 기록은 처음으로 **실제 OpenAI API(`gpt-5.6-terra`)를 호출**해 Framing과 가설 연산의 산출물 품질을 직접 평가한 결과다.

평가 주체는 **에이전트(Claude)**이며, M1a exit 기준과 ADR-D3/assess-hypothesis 축을 채점 루브릭으로 사용했다. 이는 "실제 모델 내용 품질" 공백을 메우지만, **사람 사용자의 사용성(Gate B 1·2번)이나 도메인 전문가 검증을 대체하지 않는다**(§한계 참조).

## 실행 환경

- 모델: `gpt-5.6-terra` (OpenAI, `config check` 통과 — provider/key/권한/git 모두 protected)
- 격리: 사용자 실제 `.inquiry`가 아닌 `/tmp/inq-eval/run1~5` 스크래치 디렉터리. `.env`는 복사만 하고 키 값은 출력·커밋하지 않음.
- 비대화형 구동: `framing start → next → answer` 루프를 드라이버 스크립트로 반복, 연산은 `branch propose` / `explore propose {deepen,challenge,synthesize}` CLI 직접 호출.
- 실제 API 호출 약 20여 회 발생(5종 Framing + 4종 연산 + 교차검증). 커밋·푸시·사용자 데이터 변경 없음.

## Framing 품질 (5종 입력, M1a exit 기준)

연구·제품/정책·정책·창작·사고실험 5종 seed를 실제로 완주했다. 각 세션은 3~4라운드(질문 5개 내외)에서 프레임이 수렴했다.

| seed 유형 | 입력 요지 | 질문 비유도성 | 3~5문항 수렴 | 중심질문+판단기준+범위 | 가설 상호 차별성 |
|---|---|---|---|---|---|
| 제품/정책 | 재택근무와 팀 생산성 | 통과 | 5문항 | 통과 (3정책×3지표 중심질문, 기준 3·scope include/exclude) | 통과 (비동기 성숙도 / 업무유형 배분 / 대면 즉시성) |
| 연구 | 수면 부족과 장기 기억 | 통과 | 5문항 | 통과 (단계×기억유형 메커니즘 + 메타분석 상충) | 통과 (단계-유형 선택성 / 공고화 기제 / 문헌 이질성) |
| 정책 | 공유 자전거 확대 결정 | 통과 | 6문항 | 통과 (3선택지 비용·편익 중심질문) | 통과 (공공 확대 / 현행 유지 / 민간 위탁) |
| 창작 | 주인공의 멘토 배신 설득력 | 통과 | 5문항 | 통과 (납득·충격 공존 + 복선 설계) | 통과 (선제적 배신 / 충성 충돌 / 복선 모호성 / 역설적 충성, 4개) |
| 사고실험 | 거짓말 불가능 사회 | 통과 | 5문항 | 통과 (계약·사법·외교 재편) | 통과 (검증비용 / 공개강제 / 전략적모호성 / 질문설계, 4개) |

**관찰**

- 질문은 전부 개방형·명료화 목적이며 특정 답을 유도하지 않았다. seed의 목적(explore/decide)을 추론해 control mode를 전환하고 그에 맞는 후속 질문을 생성했다(예: 정책형에서 "검토 선택지는?" 추가).
- 모든 프레임이 중심 질문·purpose·use_context·current_belief·판단 기준·scope(include/exclude)·open_questions를 빠짐없이 채웠다.
- 가설은 모두 명시적 `difference` 필드로 차별 축을 밝혔고, 실제로 서로 다른 설명 축에 앵커했다(중복 아님). 창작·사고실험에서는 4개까지 생성하며 성격이 겹치지 않았다.

**판정: Framing 산출물 품질은 M1a 세 기준을 5종 모두에서 충족.**

## 연산 산출물 품질 (fork/deepen/challenge/synthesize)

재택근무 inquiry(run1)의 H-001("전면 재택은 비동기 개발 흐름을 강화한다")에 대해 실행.

- **fork(branch propose):** 부모를 세 축으로 분해한 자식 가설 3개(리뷰 규율 / 업무 의존성 / 문서화 수준) 생성. 각 자식이 부모의 3개 지표(리뷰·배포·소통)에 정확히 대응하고 상호 구분됨.
- **deepen:** 전제 5 + 반증 조건 4 + reason 추가, **claim은 변경하지 않음**. 전제·반증이 조작적(예: "요청-첫 응답 시간", "배포 자동화 수준과 변경 규모 구분")이라 실제 검증 설계로 이어질 수 있음.
- **challenge:** 반박 3개, 각각 claim+reason+**check(측정 방법)** 구조. 반박이 날카로움("강화한다기보다 기존 역량에 의존", "집중시간 ≠ 리뷰속도", "배포빈도만으로 검증 불가"). 가설을 바꾸지 않는 검토 메모로 올바르게 동작.
- **synthesize:** supported 상태의 H-001+H-002를 조건부 통합 가설로 결합. 두 부모의 긴장(재택 vs 하이브리드 우열)을 성급히 봉합하지 않고 `unresolved`에 명시. assumptions·falsified_if·reason 완비.

**교차 도메인 검증(단일 도메인 편향 방지):** 연구형 inquiry(run2, 수면-기억)의 H-001에 challenge 실행 → 수면연구 방법론 전문가 수준의 반박 생성(비특이적 각성·분절 교란 vs 단계 선택성 / 서술-절차 이분법의 과광역성 / 부호화·회수 혼입 vs 공고화). 각 반박에 수면다원검사 기반 구체적 check 포함. **연산이 정책 도메인에 과적합되지 않고 도메인 적응함을 확인.**

- `close`는 모델 생성이 아니라 `human-closed` 상태 전이(사람 결정)이므로 이 품질 평가의 대상이 아니다. 상태 머신상 `suggested→exploring→supported/contested→synthesized` 전이 규칙도 실행 중 확인했다(synthesize는 supported/contested 부모 2+ 요건).

**판정: 네 개의 모델 생성 연산 모두 claim 불변/추가 범위 준수 등 계약을 지키면서 실질적으로 유용한 내용을 생성. 2개 도메인에서 일관.**

## 한계 (통과 판정을 확대하지 않는 범위)

- **평가 주체가 에이전트다.** M1a/ADR 루브릭에 따른 내용 품질 판단이며, 사람 사용자의 이해도·사용성(Gate B 1번 최초 Framing UX, 2번 100노드 탐색)을 측정한 것이 아니다. 프로젝트 원칙(["에이전트 시각 점수로 사용성 검증을 대체하지 않는다"](m2-entry-check.md))을 유지한다.
- **답변은 평가자가 작성한 합성 입력**이다. 실제 사용자가 자신의 맥락에서 같은 품질의 프레임을 얻는지는 별도 검증이 필요하다.
- 도메인 전문가의 사실성 검수는 하지 않았다(특히 수면연구 challenge의 방법론 주장은 그럴듯하나 전문가 확인 전이다).
- 토큰 사용량·비용을 호출별로 계측하지 않았다. spend cap(D6) 실동작 검증과는 구분된다.
- run1~5는 스크래치 데이터이며 커밋하지 않았다. 재현은 동일 seed·답변으로 가능하나 모델 비결정성으로 산출물이 달라질 수 있다.

## 결론

전 보고서에서 **전무했던 "실제 모델 내용 품질"에 대한 실측 증거를 처음으로 확보**했다. 실제 `gpt-5.6-terra` 호출 기준으로 Framing(5종)과 가설 연산(4종, 2도메인)의 산출물 품질은 M1a/ADR 루브릭을 충족하며, 명백한 품질 결함(유도 질문, 가설 중복, claim 오변경, 도메인 과적합)은 관찰되지 않았다.

이는 Gate B의 리스크 중 "에이전트 산출물 품질(닭-달걀)"을 **에이전트 평가 수준에서 완화**한다. 다만 Gate B의 **사람 사용성 항목(1 최초 Framing UX, 2 100노드 탐색)과 도메인 전문가 사실성 검수는 여전히 열려 있으며**, 이 기록으로 Gate B 통과를 표시하지 않는다.
