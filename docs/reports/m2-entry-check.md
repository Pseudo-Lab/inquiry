# M2 단계별 진입 기록

2026-09-17. 정책 정본: [ADR-D7](../decisions/ADR-D7-staged-m2-gates.md).
사용자 결정: 저장·복원 코어 개발과 UX 검증을 병행하고 TUI 통합 전에 마무리한다.

## Gate A — 저장·복원 코어

| 항목 | 상태 | 근거 |
|---|---|---|
| M0 계약 | 확인 | D1~D6 Accepted, 저장·DAG·상태·독립 근거·단일 실행·사용량 요구 반영 |
| 단계별 진행 정책 | 확인 | 2026-09-17 사용자의 직접 선택, ADR-D7 |
| 범위 분리 | 확인 | 첫 구현은 저장/재생. TUI 선택·실제 API 없이 fake/임시 파일로 검증 가능 |
| critic의 확정 누락 네 가지 | 보완·재검토 OKAY | 명령 경로, draft 저장, 어댑터 선행, 중단 복구 계약 검토. [검토 기록](m2-plan-review.md) |

**Gate A 확인 완료.** M2-4B-1 Branch와 chat 연결까지 오프라인 테스트 209개와 독립 리뷰를 통과했다([최신 결과](m2-4b1-branch-eval.md)). 사용자의 chat 실행·한글 입력 삭제 문제 보고와 수정은 확인했다. 다만 질문/후보 품질·저장 후 재개 성공·실제 계정/API 결과를 모두 확인한 것은 아니므로 아래 Gate B 통과로 바꾸지 않는다. 나머지 M2-4B 연산은 계속 남아 있으며 같은 순서 결정을 반복해서 묻지 않는다.

## Gate B — M2-6 TUI 통합 전

최신 개발 상태(2026-10-01): Deepen·Challenge·Synthesize를 구현했고 전체277개·SDK 없는 operation 핵심36개·fake chat/CLI 여정·독립 코드 리뷰 APPROVE를 기록했다([결과](m2-4b-operations-eval.md)).

실제 모델 내용 품질(2026-10-07): 처음으로 실제 `gpt-5.6-terra`를 호출해 Framing 5종과 가설 연산 4종(2도메인)의 산출물 품질을 에이전트 루브릭으로 평가했고, M1a/ADR 기준 충족·명백한 결함 없음을 확인했다([품질 평가 기록](m2-model-quality-eval.md)). 이는 "에이전트 산출물 품질" 리스크를 에이전트 평가 수준에서 완화하나, 아래 Gate B의 **사람 사용성 항목(1 최초 Framing UX, 2 100노드 탐색)과 도메인 전문가 사실성 검수는 여전히 미검증**이다. 따라서 Gate B 통과 판정은 아니다.

2026-09-21 개발 업데이트: Deepen 저장·승인·CLI/chat 연결의 자동 테스트 전체 251개와 SDK 없는 관련 28개, 합성 PTY 실행을 검증했다. 최종 리뷰와 상세 결과는 [Deepen 보고서](m2-4b2-deepen-eval.md)에 기록한다. 실제 모델 보완 항목의 유용성이나 아래 Gate B 통과의 증거로 확대하지 않는다.

2026-09-20 추가 관찰: streaming 저장 병목 수정 후 사용자가 직접 테스트 완료를 보고했다([범위와 미확인 항목](interactive-framing-eval.md#사용자-직접-테스트-보고--2026-09-20)). 단계별 성공과 품질 평가가 구체적으로 보고된 것은 아니므로 아래 사용성 게이트를 자동 통과시키지 않는다. 수정 후 전체 자동 테스트 기준선은 218개다.

다음 항목은 **미검증**이며 통과로 바꾸지 않는다. 코어 개발과 병행해 수행하고 실행 일시·입력·관찰·문제·조치를 남긴다.

1. **최초 Framing UX:** 실제 사용자가 수정된 질문 안내를 보고 한 번의 탐구에서 3~5문항 안에 중심 질문·쓰임·충분성을 구체화하는지 확인한다. 담당자가 질문을 다시 풀어주거나 같은 질문을 반복했다면 그 실패를 기록한다. 기존 사용자의 답변을 새로 수집할 필요가 없는 재개 경로도 별도 확인한다. 검증 참여자는 기존 사용자일 필요가 없다.
2. **100노드 탐색:** 선택한 Git-log 화면과 기본 CLI 도움말로 지정한 가설의 부모, 합류 입력 두 개, 종료 이유를 찾아보게 한다. 누락된 노드나 틀린 연결이 없어야 하며, 설명 개입 없이 완료했는지와 페이지 이동 부담을 관찰한다. 불편을 발견하면 요약/페이지 방식을 수정하고 해당 과제를 다시 확인한다. 클릭/방향키 노드 탐색을 앞당기는 방식으로 해결하지 않는다.
3. **시각 규칙 정합:** 위→아래 계보, 옆 분기라는 선택을 PRODUCT-CONCEPT §9 및 M1b 평가 기준에 반영하고, 기존 위/아래 지지·반박 규칙과의 충돌을 없앤다.
4. **TUI 도구:** 한국어 정렬, 세 폭, 지도+명령 입력, resize, 긴 출력, 단일 실행 취소, 종료 시 터미널 복구를 작은 실험으로 확인해 도구를 선정한다. 새 의존성은 기존 승인 범위를 확인하고 필요성을 기록한다.

각 항목의 실측·사람 판단을 기록하기 전에는 Gate B 통과로 표시하지 않는다. 에이전트 시각 점수와 자동 fixture 테스트만으로 사용성 검증을 대체하지 않는다.
