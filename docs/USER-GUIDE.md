# Inquiry 사용자 안내서

Inquiry는 정답을 바로 만드는 도구가 아니라, 하나의 질문에서 나온 여러 생각을 **가설**로 남기고 근거와 검토 과정을 따라가는 로컬 탐구 도구입니다.

## 가장 짧은 시작

프로젝트 루트에서 실행합니다.

```bash
.venv/bin/python -m inquiry chat
```

탐구 기록을 코드와 분리하려면 별도 폴더를 지정합니다.

```bash
.venv/bin/python -m inquiry --dir /path/to/my-inquiry chat
```

새 모델 생성을 하려면 지정한 탐구 폴더에 `OPENAI_API_KEY`와 `INQUIRY_MODEL`을 담은 `.env`가 필요합니다. 저장된 결과를 읽거나 승인·거부하는 과정에는 API 호출이 없습니다.

## 핵심 개념

| 용어 | 뜻 | 예시 |
| --- | --- | --- |
| Inquiry | 탐구하려는 질문 또는 목표 | “반복되는 배포 실수를 어떻게 줄일까?” |
| Hypothesis / 가설 | 확인할 만한 답 또는 방향 | “배포 전 짧은 체크리스트가 실수를 줄인다.” |
| Evidence / 근거 | 가설을 지지하거나 의심하게 하는 자료·관찰 | 실제 배포 기록, 측정 결과, 사람의 판단 |
| Action | 가설을 확인하기 위한 다음 행동 | 체크리스트를 두 팀에서 2주간 시험한다. |

가설은 사실이나 결정이 아닙니다. 탐구 중인 생각을 명확히 기록하는 단위입니다.

## 가설의 상태

```text
suggested → exploring → supported / contested
                              ↓
                    Synthesize (둘 이상)
                              ↓
                    새 suggested 통합 가설
```

| 상태 | 뜻 |
| --- | --- |
| `suggested` | 막 만들었으며 아직 본격적으로 검토하지 않은 가설 |
| `exploring` | 지금 조사·검증하고 있는 가설 |
| `supported` | 현재 근거가 가설을 지지한다고 사람이 판단한 상태. 확정된 진실은 아님 |
| `contested` | 지지 근거가 있어도 중요한 반론·불확실성이 남은 상태 |
| `synthesized` | 다른 가설들과 함께 새 통합 가설을 만드는 데 사용된 상태 |

## Check 메뉴 사용법

승인된 탐구의 루트 메뉴에서 `3. Check`를 선택합니다.

### Deepen — 한 가설을 더 선명하게

기존 주장 자체를 바꾸지 않고 다음을 제안받습니다.

- 가설이 성립하려면 필요한 전제
- 가설이 틀렸다고 볼 조건
- 왜 이 보완이 필요한지에 대한 이유

승인 전에는 가설이 바뀌지 않습니다. 승인 후에도 제목·주장·부모·상태는 유지되며, 전제와 반증 조건만 추가됩니다.

### Challenge — 약점과 반론을 검토하기

가설에 대한 반론, 그 이유, 확인 방법을 검토 메모로 제안받습니다. 승인해도 가설 상태·주장·근거·가지 수는 바뀌지 않습니다. Challenge는 모델의 의견이며 독립적인 Evidence가 아닙니다.

`Review Notes`에서 승인한 메모를 다시 읽을 수 있습니다.

### Synthesize — 검토된 가설을 통합하기

`supported` 또는 `contested` 상태의 서로 다른 가설이 둘 이상일 때만 메뉴에 나타납니다. 예를 들어 다음 두 가설이 충분히 검토되었다고 합시다.

- “짧은 배포 기록이 반복 실수를 줄인다.”
- “실행 전 검증이 반복 실수를 줄인다.”

Synthesize는 이를 “짧은 기록과 실행 전 검증을 함께 사용하면 반복 실수를 줄인다”처럼 새 가설로 제안합니다. `Unresolved`에는 통합해도 아직 답하지 못한 차이를 남깁니다.

승인하면 한 번의 저장으로 다음이 함께 일어납니다.

1. 새 `SYN-*` 가설이 `suggested` 상태로 생성됩니다.
2. 선택한 모든 부모가 `synthesized` 상태가 됩니다.
3. 새 가설의 부모 연결에 선택한 가설들이 기록됩니다.

부모 중 하나라도 제안 생성 뒤에 바뀌었다면 제안은 `Stale`입니다. 이 경우 새 가설을 만들거나 일부 부모만 전환할 수 없으며, 거부 후 새로 생성해야 합니다.

## 저장·재개·비용

`Save & Exit`는 현재 제안을 저장하고 종료합니다. 다음 실행에서 같은 제안을 열면 모델을 재호출하지 않습니다. 새 모델 요청은 `Generate`를 명시적으로 선택했을 때만 발생하며 비용이 청구될 수 있습니다.

모델 실행이 중단되면 `Resume`은 저장된 실행 상태만 복구합니다. 모델을 자동으로 다시 요청하지 않으므로, 복구 뒤에는 직접 `Generate`를 선택해야 합니다.

## Synthesize가 보이지 않을 때

다음 조건을 확인하세요.

1. 탐구에 가설이 두 개 이상 있는가?
2. 그중 두 개 이상이 `supported` 또는 `contested` 상태인가?
3. 같은 가설을 두 번 선택하려는 것은 아닌가?

현재 chat 화면은 가설 상태를 바꾸는 화면을 아직 제공하지 않습니다. 근거 추가와 상태 전환은 단발 CLI 명령으로 준비해야 합니다. 이 제한은 Git-log TUI와 Actions 기능이 Gate B 뒤에 통합되기 전까지 유지됩니다.

## 기억할 원칙

- 모델 제안은 사람이 승인하기 전까지 탐구 그래프를 바꾸지 않습니다.
- `supported`는 “현재 근거가 지지한다”는 뜻이지 “사실로 확정됐다”는 뜻이 아닙니다.
- Challenge 메모와 Synthesize의 `Unresolved`는 검증된 근거가 아닙니다.
- 취소·재개·조회는 저장된 상태를 보존하며 자동 재시도하지 않습니다.
