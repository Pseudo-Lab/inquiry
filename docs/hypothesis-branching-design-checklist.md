# 가설 분기 설계 체크리스트

> 목적: Inquiry가 하나의 질문에서 경쟁 가설을 **생성·분기**할 때(framing / branch / synthesize 연산) 따라야 할, **근거 있는 설계 기준**. 채점(평가) 기준이 아니라 **생성 시점의 설계 기준**이다.
> 근거: [로지컬 분기 방법론 리서치](reports/logical-branching-methodology-research.md) · 관련: [PRODUCT-CONCEPT §7·§9](PRODUCT-CONCEPT.md) · [ADR-D2 DAG-only](decisions/ADR-D2-graph-model.md) · 채점은 [assess-hypothesis 스킬](../.claude/skills/assess-hypothesis/SKILL.md)로 분리.
> 상태: v0 초안 (2026-10-08). 사례가 쌓이면 교정.

## 왜 "생성"과 "평가"를 나누는가 (전제)

Peirce 귀추법 해석(Yu & Zenker 2018)은 **가설 "생성"(abduction)과 가설 "평가·선택"(IBE)을 별개 범주로 유지**하라고 논증한다. 이 문서는 **생성 쪽만** 다룬다. 품질 채점(plausibility·evidence_strength·novelty·impact·testability 5축)은 생성이 끝난 뒤 `assess-hypothesis`가 따로 한다.

→ **분기를 만들 때 채점 축을 섞지 말 것.** 생성 단계에서 유일하게 쓰는 평가는 `plausibility`에 의한 **1차 컷**뿐이다(아래 P6).

## 설계 원칙 체크리스트 (P1–P6)

각 원칙은 분기 산출물을 두고 던지는 **예/아니오 점검 질문**으로 쓴다.

### P1 — 처음부터 복수·동시 분기
**근거:** Chamberlin(1890/1897) 다중 작업 가설법 — 단일 가설은 무의식적 선택적 주의(확증 과장·반증 방치)를 부른다. 해법은 여러 설명을 **병렬로** 전개해 "애정"을 분산하는 것.

- [ ] 한 질문에 **2개 이상**의 경쟁 가설을 동시에 세웠는가? (단일 가설로 출발하지 않았는가)
- [ ] 어느 하나가 "정답 후보"로 미리 특권화되어 있지 않은가?

### P2 — 각 가설은 자기 반증조건을 내장
**근거:** Platt(1964) strong inference — 좋은 가설은 "어떤 결정적 관찰이 나를 배제하는가"를 품는다. Peirce의 좋은 abduction 기준도 **검증 가능성**.

- [ ] 각 가설에 **무엇이 관측되면 이 가설이 틀리는지**(`falsified_if`)가 적혀 있는가?
- [ ] 그 반증조건이 "원리상 불가능"이 아니라 **현실적으로 관측 가능**한가?

### P3 — 배타적 경쟁 + 공조(부분 기여) 둘 다 허용
**근거:** Chamberlin — 복잡한 현상은 대개 단일 원인이 아니라 **여러 공조 원인**의 산물이다(단일 가설법은 이를 못 담아 "무능"). 5대호 = 하천 계곡 + 빙하 굴식 + 지각 변형.

- [ ] 가설들이 **상호 배타**(하나만 참)인지, **공조 가능**(여럿이 함께 부분 기여)인지 구분했는가?
- [ ] 공조 가능이라면, 나중에 **종합(synthesize)할 경로**를 DAG가 허용하는가? (승자독식으로 강제하지 않는가)

### P4 — 생성 단계에서 채점하지 말 것
**근거:** Yu & Zenker(2018) — 생성 ≠ 평가.

- [ ] 분기를 **만드는 동안** 5축 점수를 매기지 않았는가? (채점은 `assess-hypothesis`에서 별도로)
- [ ] 생성 산출물이 "점수"가 아니라 **claim · assumptions · falsified_if**의 구조로 나왔는가?

### P5 — 형제 가설은 서로 구별 가능해야
**근거:** Yanco et al.(2020) — 경쟁 가설은 **예측 분포가 겹치면** 어떤 증거로도 구별 못 해 무용하다. 데이터 수집 전에 "분포 간 중첩"을 정량화하라.

- [ ] 형제 가설들이 **같은 증거에 대해 서로 다른 예측/함의**를 내는가? (표현만 다른 중복이 아닌가 — M1a "중복 아님"의 조작적 버전)
- [ ] "이 증거가 나오면 A는 지지되고 B는 배제된다"를 **각 쌍에 대해 말할 수 있는가?** 말 못 하면 두 가설은 아직 구별 안 됨 → 분기를 다시.

### P6 — plausibility로 1차 컷, 불확실한 가지 우선 심화
**근거:** Peirce "연구 경제성"(Yu & Zenker) — 가능 가설은 무한, **타당한(plausible) 가설 집합은 유한**. plausibility로 순서를 매겨 덜 타당한 것을 배제. HypoAgents(2025) — **정보 엔트로피가 높은(불확실한)** 가설 가지를 우선 정제.

- [ ] 명백히 **성립 불가능한(plausibility L0)** 가지를 걸러냈는가? (단, 그 외에는 생성 단계에서 더 채점하지 말 것 — P4)
- [ ] 다음에 **deepen할 대상**을 고를 때, 가장 확신에 찬 가설이 아니라 **가장 불확실하면서 impact 있는** 가설을 우선했는가?

## 연산별 적용 매핑

| 연산 | 적용 원칙 | 핵심 점검 |
|---|---|---|
| **framing** (초기 가설 후보) | P1, P4, P5 | 2+ 후보, 서로 구별, 채점 안 섞기 |
| **branch** (자식 가설) | P1, P2, P5 | 부모를 서로 다른 축으로 분해, 각자 반증조건 |
| **deepen** | P2, P6 | 전제·반증조건 보강, 불확실한 가지 우선 |
| **synthesize** | P3 | 공조 가설을 상위 결론으로 종합(DAG in-degree>1) |
| **challenge** | P2 | "어떤 관측이 이걸 배제하나"를 명시 |

## 채점 축과의 관계 (범위 밖 명시)

이 체크리스트는 **생성 설계**만 다룬다. 5개 채점 축 중:

- **생성 설계에 직접 관련:** `plausibility`(1차 컷, P6), `testability`(반증조건, P2) — 그리고 축에는 없지만 **구별가능성**(P5, Yanco)이 분기 설계의 핵심 기준.
- **생성 설계와 무관(= 사후 평가·우선순위 축):** `evidence_strength`(증거는 생성 후 수집), `novelty`(반복 감지), `impact`(결정 관련성).

> ⚠️ **열린 질문 (사용자 지적 2026-10-08):** `impact`·`novelty`는 성격상 **"연구/논문 가치 평가"에 가까운 축**이라, Inquiry 코어의 분기·탐구 흐름에 꼭 필요한지 재검토 여지가 있다. 리서치에서도 `impact`는 과학방법론 문헌에 **직접 근거가 약했고**(HypoAgents의 'relevance', Peirce '연구 경제성'이 근접할 뿐), `novelty`는 HypoAgents N-R-F에만 대응했다. 단 CAL-002에서 `impact×testability` 분리가 "비전가설 식별"이라는 실용 가치를 보인 바 있어, **제거가 아니라 "코어 vs 논문용" 역할 구분**으로 다룰 사안. → 채점 rubric(assess-hypothesis / ADR-D3) 차원의 별도 결정으로 남긴다. 이 설계 체크리스트에서는 두 축을 **쓰지 않는다.**
