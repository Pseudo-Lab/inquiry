# M3-D6 Spend Cap (Token Budget) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` for sequential implementation, or `subagent-driven-development` for bounded delegated work. Apply `test-driven-development` and `verification-before-completion` for each task. 체크박스는 검증 후에만 완료로 바꾼다.

**Goal:** ADR-D6가 결정한 inquiry별 **spend cap**을 런타임에 구현한다. inquiry 전체 누적 토큰이 cap을 넘으면 **신규 agent run을 차단**하고, 사람이 cap을 상향하면 재개한다(§4.4 "사람이 경계를 가진다"). M3 추천 순서 2번째 항목으로, **다중 actor(3번) 전의 비용 폭주 안전장치**다(리스크 표: "spend cap 미구현이면 다중 에이전트 지연").

**Architecture:** 이벤트 소싱(`events` 검증 → `replay` projection → `model` dataclass) 재사용. cap은 `SpendCapSet` 이벤트로 저장하고 `State.spend_cap`에 투영한다. 차단은 **모든 run이 거치는 공통 지점 `Runner.execute`의 본문**(사전검사 구간, `runs.py:102-103` "unfinished runs" 체크 직후, `preflight` 훅 호출 전) 한 곳에서 `state.spend_cap`/`state.runs`로 판정한다 — `preflight` 훅이 아니라 execute 본문이다. 4개 서비스(framing·branch·operation·assessment)를 자동 커버한다. cap 설정(쓰기)은 run이 없는 순수 human 명령이므로 `Commands`의 `_commit` 패턴을 재사용한다.

**Tech Stack:** Python 3.9+, 표준 라이브러리 unittest, 기존 `.venv`. 새 의존성 없음.

**Status:** 2026-10-12 계획 수립 → critic 1회차 CHANGES NEEDED → B1~B3·G1~G4·D1~D3 반영해 개정 → **Task 1~3·5 구현·검증 완료, Task 4(TUI) 표현계층으로 이월.** 기능 코어(이벤트·차단·CLI·경고) 완결. 신규 25 테스트, 전체 103 그린.

**선행 결정 (사용자 확정 2026-10-12):**
- **메트릭: 토큰 기반.** `est_cost`는 openai_adapter에서 항상 None(`openai_adapter.py:90`, 금액 미계산)이라 cost(금액) cap은 불가. `Runner.totals()`가 집계하는 input+output 토큰으로 cap. 금액 cap은 가격표 연동 시 후속.
- **기본 cap: opt-in(미설정).** cap 설정 전엔 무제한. `budget set`으로 켠다. 기존 동작과 호환. 적정 기본값은 M3 실측 후 결정.
- **soft cap(사후 누적).** 누적 known-usage 토큰 ≥ cap이면 **다음 run 차단**. 진행 중 run 비용은 예측 차감 안 함(overshoot 최대 run 1회).
- **(D1) cap 설정은 inquiry 존재 시에만.** `SpendCapSet`은 inquiry 선행 요구. framing 단계(inquiry 생성 전)엔 cap 미적용(cost bounded). 일반 흐름 init→budget set→agent run.
- **(D2) `reason` 빈 문자열 허용.** 기존 `Commands.decide` 등과 일관.
- **(D3) near 경고 임계 90% 기본.** 정확 수치는 열린 질문 유지(ADR이 M3 실측으로 미룸).

## Global Constraints

- 정본: [ADR-D6](../../decisions/ADR-D6-cost-model.md), [ADR-D4(agent-adapter)](../../decisions/ADR-D4-agent-adapter.md), [MILESTONES §M3](../../MILESTONES.md).
- **집계 단위(ADR-D6):** inquiry 전체 누적 = 모든 run의 토큰 합. 집계 규칙은 기존 `totals()`와 동일 — **`status != 'known'`(unknown·not-started·started)은 제외**(started run의 usage는 `unknown_usage()`라 자동 제외). "known만 합산"이 아니라 "unknown-류 제외"가 정확한 표현.
- **집계 타이밍(검증됨):** `replay.py`가 동시 미완 run을 금지(한 번에 `started` 최대 1개)하고 cap 체크는 `started` run 생성 전이므로, 판정 시점에 완료된 run 누적만 보면 된다. 진행 중 run의 미보고 토큰은 고려 불필요.
- **차단 지점:** `Runner.execute` 본문의 `runs.py:103` 직후(= `preflight` 훅 **이전**, RunStarted 기록 **이전**). `state.spend_cap`이 None이 아니고 누적 ≥ cap이면 `ValueError`(used/cap + "raise the cap to resume")를 raise. **`preflight` 훅에 넣지 않는다**(framing의 cancelled-before-dispatch 경로와 꼬임 방지).
- **차단 전파(검증됨):** cap 초과 시 execute는 run 객체 대신 `ValueError`를 던진다(기존 "unfinished runs" 체크와 동일 방식). 4개 서비스는 이 예외를 잡지 않고 그대로 전파(CLI가 `cli.py`에서 잡아 출력). framing의 `run.status=='cancelled'` 성공 분기(`framing/service.py:210`)와 혼동 없음 — cap 예외는 `run` 변수 생성 전(line 207)에서 발생.
- **recover 무영향(검증됨):** `Runner.recover()`는 execute를 거치지 않고 `RunFailed(system:recovery)`만 기록 → cap 체크 대상 아님(복구는 신규 run 아님).
- **재개:** 사람이 `SpendCapSet`(더 큰 값)으로 cap 상향 시 재개. cap 설정은 `human:local` 액터. replay의 SpendCapSet 분기에서 **`event['actor']=='human:local'` 검증**.
- **근접 경고(ADR-D6 line 17·29):** 차단만으론 부족 — run 성공 **후** 누적이 cap의 임계(기본 90%) 이상이면 CLI가 경고를 노출(stderr). `budget_status().near` 플래그 + run 명령(branch/explore/assess) 뒤 공용 경고 헬퍼.
- **가짜 정밀도 금지(ADR-D6/§10):** 토큰은 실측이라 정확 표시 OK. 비용 "진행률" 추정 표시는 만들지 않는다.
- **범위(이번 슬라이스): 토큰 cost cap만.** 깊이 상한·시간 상한(run timeout 외)은 ADR이 언급하나 후속(현 코드 없음). run 단위 timeout은 기존 유지.
- `.env`·실제 `.inquiry`·사용자 설치 환경은 읽거나 수정하지 않는다. 테스트는 합성 데이터와 TemporaryDirectory. 실제 API·커밋·푸시는 별도 요청 전 금지.
- 기존 `schema_version=1` 로그 호환. 새 kind는 명시 검증하고 구버전 프로그램이 거부하는 동작 유지. cap 미설정 로그 = 기존 동작.
- 구현 순서 Task 1→2→3→4→5. 각 단계 통과 전 다음으로 확장 금지.

## Tasks

### Task 1 — `SpendCapSet` 이벤트 + `State.spend_cap` 투영 ✅ (2026-10-12)
- `domain/model.py`: `State.spend_cap: Optional[int] = None`.
- `domain/events.py`: `CHANGE_FIELDS['SpendCapSet']` 등록 + validate_event 분기(`max_tokens` 양의 정수, `reason` 문자열·빈 허용).
- `domain/replay.py`: `SpendCapSet` 분기 — **inquiry 선행 요구**(없으면 ReplayError), **`event['actor']=='human:local'` 검증**, 최신 `max_tokens`가 `spend_cap` 덮어씀, `State(...)` 13-인자 호출에 전달.
- **수용 기준:** SpendCapSet replay 후 `State.spend_cap` 설정, 두 번 설정 시 최신값. `max_tokens` 0·음수·비정수 거부. inquiry 선행 없으면 거부, 비-human 액터 거부. 미설정 로그 → `spend_cap=None`. `State(...)` 호출·`asdict(state)`(cli show) 무회귀(출력에 `spend_cap` 포함 확인).
- **결과:** model/events/replay 반영. replay `SpendCapSet` 분기는 inquiry 선행 + `role=='human'` 액터 검증 + 최신값. `tests/test_spend_cap_events.py` 10개 통과, 전체 88개 그린(무회귀).

### Task 2 — `Runner.execute` 차단 + `budget_status()` ✅ (2026-10-12)
- `llm/runs.py`: `execute` 본문 line 103 직후(preflight 훅 전, RunStarted 전) cap 체크 — `state.spend_cap`이 설정됐고 누적 known 토큰 ≥ cap이면 `ValueError`. 누적은 `totals()`와 동일 규칙.
- 신규 `budget_status()` 반환 `{cap, used_tokens, remaining, over, near, unknown_runs}`(near = cap 설정 + used ≥ 0.9*cap). `totals()`는 변경 없음.
- **수용 기준:** cap 미설정 → 절대 차단 안 함(기존 무회귀). 누적 < cap → 정상. 누적 ≥ cap → 신규 run 거부(ValueError). cap 상향 후 재개. **ValueError 전파 테스트**: 최소 1개 서비스(예: operation/assessment) + framing에서 cap 초과 시 run 객체 아닌 예외가 올라오고 framing cancelled 분기와 혼동 없음. recover()는 cap 무관(미경유) 확인.
- **결과:** `execute` 사전검사에 cap 차단(ValueError), `_used_tokens`+`budget_status()` 추가(`totals()` 불변). service(assessment) 경유 차단/재개 + budget_status 플래그 + recover 무영향 검증. `tests/test_spend_cap_runner.py` 7개 통과, 전체 95개 그린. (framing 전파는 동일 execute 공통 지점이라 기계적으로 동일 — Task 3 CLI/통합에서 추가 확인 가능.)

### Task 3 — `Commands.set_cap` + CLI `budget` ✅ (2026-10-12)
- `commands.py`: `set_cap(max_tokens, reason='')` — `_commit`로 `SpendCapSet` 커밋(`human:local`, 낙관적 락). max_tokens 양의 정수 검증.
- `ui/cli.py`: `budget show`(budget_status JSON) / `budget set --max-tokens N [--reason]`. run 명령(branch/explore/assess) 성공 뒤 `near`면 공용 헬퍼로 stderr 경고.
- **수용 기준:** set→show 왕복. over/near 플래그 정확. 키 없이 조회·설정 가능(합성 데이터). cap 상향 시 차단 해제. near일 때 run 명령이 경고 출력.
- **결과:** `Commands.set_cap`(inquiry 선행·양의 정수 검증, `_commit` 재사용). CLI `budget show|set`, run 명령(branch/explore/assess) 뒤 `_warn_if_near`로 stderr 경고(G1). 실제 CLI 스모크(show/set) 확인. `tests/test_spend_cap_cli.py` 8개 통과, 전체 103개 그린.

### Task 4 — TUI 상태줄 노출 (thin, 후순위 가능) — ⏭️ 이월 (표현계층)

- `ui/tui.py` 상태줄에 `used/cap`(미설정 시 `used tokens`) 표시. `budget_status()` 재사용.
- **수용 기준:** 상태줄에 누적(+cap) 노출, cap 초과 시 시각 경고. 문자열 생성 함수 단위로 검증(TUI 통합 테스트 난이도 고려).

### Task 5 — ADR-D6 운용 결정 반영 (문서) ✅ (2026-10-12)

- **수용 기준:** ADR-D6가 코드 동작과 정합. 기본 cap 수치·near 정확 임계는 열린 질문 유지.
