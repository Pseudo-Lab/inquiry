# Pivot to monitor/control-plane — Phase 0–1

> 전략 전환([ADR-D12](../../decisions/ADR-D12-monitor-control-plane.md)) 구현 계획. inquiry = 공유 탐구 그래프 + MCP 인제스천 + 멀티에이전트 모니터. 외부 harness 에이전트가 가설을 생성, inquiry는 수용·모니터.

**선행 결정 (사용자 확정 2026-10-12):** 모니터/control-plane 전환 · MCP 인제스천 · 공유 그래프(에이전트=`agent:<name>`) · self-run(openai_adapter·Runner·spend-cap)은 optional 보존 · 세션/pane은 orca.

## Phase 0 — 문서 (전략 기록) ✅ (2026-10-12)
- ADR-D12 신규(피벗 결정) + README 등록.
- ADR-D4(agent-adapter)·D8(로컬 BYOK)에 "self-run 한정, 주력은 harness" 재해석 노트.
- MILESTONES §M3에 피벗 노트 + "근거 기반 가설 제안" 재프레이밍(리서치 커넥터=harness).

## Phase 1 — MCP 인제스천 + 모니터 MVP ✅ (2026-10-12)
- `features/ingest/service.py` `IngestService(root, agent)`: `add_hypothesis`·`add_evidence`를 **`agent:<name>` actor로 커밋**(이벤트 소싱 코어 재사용, 임의 세션명 허용·`:`금지). 인콰이어리는 사람이 부트스트랩 전제.
- `monitor.py` `summary(events, state)`: 상태별 가설 수·기여 agent·saturation(D11)·near-duplicates·최근 활동. 순수.
- `mcp_server.py`: `add_hypothesis`/`add_evidence`/`status` 핸들러(dep-free, 테스트됨) + `build_server()`/`serve()`(lazy import). **mcp 2.x(`MCPServer`)·1.x(`FastMCP`) 둘 다 지원**, 미설치 시 명확한 안내. tool 3종.
  - **실제 MCP stdio 검증(2026-10-12, mcp 2.3.0):** 클라이언트가 서버를 stdio로 띄워 `list_tools`→`inquiry_add_hypothesis`(H-001)→`inquiry_add_evidence`(E-001)→`inquiry_status`(agents=[agent:claude-session]) 왕복 성공, 잘못된 target은 `is_error`로 반환. Claude Code가 쓰는 전송과 동일.
- `ui/cli.py`: `inquiry status`(모니터 JSON) + `inquiry mcp --agent <name>`(서버 실행).
- **검증:** `tests/test_ingest_monitor.py`(8)·`test_mcp_and_status.py`(6). 전체 155 그린. CLI 스모크: status 동작, mcp 미설치 시 안내. 두 에이전트가 한 그래프에 기여 + 교차 near-duplicate 확인.

**아키텍처 payoff:** 사람-에이전트 분업이 D5(_AGENT_EDGES)+D10(actor)로 이미 강제 — 에이전트는 제안/탐색만, 사람이 터미널 결정 확정. 코어 변경 0, 추가만.

## Phase 2 — 모니터 대시보드 ✅ (2026-10-12)
- `monitor.render_text(summary)`: 사람용 텍스트 대시보드(inquiry·상태별 가설·기여 agent·saturation 배너·near-duplicate·최근 활동). 순수.
- `ui/cli`: `inquiry monitor [--window][--threshold][--watch N]` — `status`(JSON)는 orca/에이전트용 유지, `monitor`는 사람용 텍스트. `--watch`는 N초마다 화면 갱신(라이브).
- ADR-D12 열린 질문(모니터 TUI vs orca 렌더)을 **최소 후회**로 해소: 텍스트 라이브 + JSON API 둘 다, 무거운 Textual 미도입. 리치 TUI/orca 렌더는 선택적 후속.
- **검증:** `tests/test_monitor_dashboard.py`(5). 전체 160 그린. 실측: 교차 에이전트 near-duplicate가 대시보드에 표시.

## Phase 3 — 사람 게이트 triage surface ✅ (2026-10-12)
- `monitor.review(events, state)`: 에이전트 산출물 중 **사람 결정 대기**를 그룹핑 — `triage`(suggested: start/close)·`decide`(exploring+evidence: support/contest/refute)·`resolve`(contested). 각 항목에 제안 agent·evidence·near-dup 플래그·추천 액션. 순수.
- `monitor.render_review(groups)`: 사람용 텍스트 triage.
- `ui/cli`: `inquiry review [--threshold][--json]` (기본 텍스트, `--json` 구조화). 결정 메커니즘은 기존 start/support/contest/refute/… 재사용(새 결정 코드 0).
- **검증:** `tests/test_review_gate.py`(9). 전체 169 그린. 실측 루프: 에이전트 제안→Triage(귀속)→사람 start+에이전트 근거→Decide(근거 수).

## 견고성/UX 후속 ✅ (2026-10-12)
- **동시 쓰기 자동 재시도(Option 2):** 멀티에이전트 동시 push 시 `StoreBusyError`/`StoreConflictError`를 지수 백오프 재시도(`store.retry_on_contention`), IngestService·Commands commit에 적용. I/O 실패는 비재시도. (PR #23)
- **파일 변경 기반 모니터(Option 1):** `Store.signature()`((mtime,size)) + `monitor --follow` — 변경 시에만 재렌더(idle replay/렌더 0, 거의 즉시 반영). 의존성 없음. true inotify(watchdog)는 후속 lazy 옵션.
