# 대화형 Framing → 승인 후 Git-log 화면 설계

- 작성일: 2026-09-20
- 상태: 화면 전환 방향과 번호형 승인/거부/저장 후 종료 방식 사용자 승인. `chat` 대화형 진입 구현·자동 검증 완료; 실제 사용성/Gate B는 미검증. [검증 기록](../../reports/interactive-framing-eval.md).
- 결정: [ADR-D9](../../decisions/ADR-D9-conversation-before-map.md)
- 선행 조건: [ADR-D7](../../decisions/ADR-D7-staged-m2-gates.md)의 Gate B 유지

## 목적

현재 테스트용 CLI의 긴 세션/질문 ID 복사와 JSON 읽기를 없앤다. 사용자는 한 번 실행한 뒤 생각 입력, 질문 답변, 제안 확인과 승인까지 화면 안에서 이어간다. 승인 전에는 대화에 집중하고, 저장 성공 후에 실제 가설의 Git-log 화면으로 전환한다.

## 범위와 진행 순서

1. **대화형 진입:** 일반 터미널의 순차 질문·응답으로 기존 FramingService를 연결한다. 이 단계에는 지속형 지도나 TUI 프레임워크를 넣지 않는다. 최초 Framing UX를 직접 검증할 수 있는 경로다.
2. **Gate B 검증:** 최초 질문 UX, 100노드 탐색, 시각 규칙 정합, TUI 도구의 한국어/resize/입력/종료 복구를 기존 평가 문서에 기록한다. 자동 테스트만으로 통과 처리하지 않는다.
3. **승인 후 지도 연결:** Gate B 확인 후 선택된 Git-log를 실제 State에 연결한다. 임의 DAG와 페이지 경계 연결을 검증하고, 대화형 진입에서 승인 후 같은 실행 안의 지도 화면으로 전환한다.

이 순서는 M2-6 통합을 앞당겨 Gate B를 우회하는 결정이 아니다. M2-4B의 AI 탐구 연산과 M2-5의 Actions/문서 출력 완료를 주장하지 않는다. 이번 좁은 연결 범위는 Framing과 실제 저장 상태 표시이며 전체 M2 완료는 별도다.

## 사용자 흐름

### 시작과 재개

- 기존 단발 명령을 유지하고 `python -m inquiry chat`을 추가했다. 대화 루프는 `interactive.py`, 진입/지연 공급자 연결은 `cli.py`가 담당한다. 아래 Git-log 단계는 아직 실행 가능한 기능이 아니다.
- 탐구가 없는 디렉터리에서는 생각을 입력받고 draft를 저장한다.
- draft가 하나면 저장된 미응답 질문 또는 pending 제안을 복원한다. 여러 draft면 seed 요약과 상태를 번호 목록으로 보여 주어 선택하게 한다. 긴 ID 입력을 요구하지 않는다.
- 이미 승인된 inquiry면 Gate B 이후 구현에서는 지도로 바로 진입한다. 그 전 대화형 단계에서는 저장된 탐구 요약만 표시하고 지도가 아직 연결되지 않았다고 안내한다.
- 조회·재개·승인은 키나 네트워크 없이 동작한다. 새 모델 생성 직전에만 설정/SDK를 검사하고 공급자·모델·문맥 전송·비용을 알린다. 실키를 화면에 표시하지 않는다.

### 질문과 답변

- 처음 질문 묶음은 기존 계약대로 3개를 생성·저장하지만 화면에는 **미응답 질문을 하나씩** 보여 준다. 질문이 필요한 이유와 `Question 1 / 3` 같은 현재 묶음 진행을 표시한다. 추가 질문이 있을 수 있으므로 처음부터 전체가 3개라고 약속하지 않는다.
- 답변을 제출하면 저장 완료 후 다음 질문으로 이동한다. 빈 답변은 다시 입력받고, 모르면 사용자가 `모르겠어요`라고 명시적으로 답할 수 있다.
- 누적 3~5문항 제한을 유지하며 이미 제출한 질문을 다시 묻거나 답변을 덮어쓰지 않는다.
- 실행 중에는 실제 실행 상태를 표시한다. 가짜 진행률이나 꾸며낸 heartbeat를 만들지 않는다. 프레임 생성이 끝나기 전 부분 JSON을 완성된 제안처럼 표시하지 않는다.

### 제안과 승인

- 중심 질문·목적·사용 맥락·현재 생각·판단 기준·범위·열린 질문·후보를 읽기 쉬운 텍스트로 표시한다. 내부 JSON/UUID는 일반 화면의 중심에 두지 않는다.
- 선택지는 `Accept`, `Reject`, `Save & Exit`다. 번호 입력으로 선택하고, 승인에는 저장된 proposal ID를 내부적으로 사용한다.
- `Reject`는 이유를 저장하고 기존 제안을 남긴다. 별도의 `Regenerate` 선택 전에는 다시 과금 호출하지 않는다. 자유 편집/과거 답변 수정 기능을 새로 추가하지 않는다.
- `Accept`의 원자적 저장이 끝난 뒤에만 지도 화면으로 넘어간다. 초기 가설은 `Suggested`이며 자동으로 탐색 상태로 바꾸지 않는다.

### Git-log 화면 — Gate B 이후

- 사용자가 선택한 박스 안 세로형 Git-log와 고정 열을 유지한다. 프레이밍 중 빈 지도는 표시하지 않는다.
- 지도는 저장된 가설 ID·부모·상태의 투영이다. 실제로 분기나 합류가 없다면 선을 꾸며 넣지 않는다. 최초 후보들이 서로 독립적이면 별개의 루트로 표시한다.
- 명령 입력 영역과 실행 상태를 지도의 별도 영역에 두어 긴 출력이 지도를 밀어내지 않게 한다. UI 용어는 영어, 사용자 내용은 원문 언어를 유지한다.
- 페이지 이동은 번호/명령으로 제공한다. 페이지 밖 부모·합류 입력은 경계 ID와 숨긴 개수를 표시하고 모든 노드에 접근할 수 있어야 한다. 프로토타입의 고정 3개 lane/18페이지를 제품 제한으로 가져오지 않는다.
- 기본 상세는 기존 `show <id>` 의미를 유지한다. 클릭·방향키로 노드를 선택하는 상세 패널은 MVP 이후 범위다.
- 가설 분기·심화·반론·통합의 AI 기능을 구현된 것처럼 보여주지 않는다. 실제 지원되는 명령만 Help에 표시한다. Actions와 export도 구현된 시점에만 노출한다.

## 중단과 실패

- 질문 입력 중 종료하면 제출된 답변만 유지한다. 미제출 키 입력은 복원하지 않는다.
- 모델 실행 중 취소는 기존 Run/Framing 취소 경계를 따른다. 이미 저장된 결과와 미확인 실행을 구분하며 자동 재호출하지 않는다.
- 재개할 때 취소한 draft는 사용자 재개 선택 후 이어간다. 미종결 Run은 명시적 복구 후 실패/미확인 상태로 표시한다.
- 설정·인증·응답 검증 오류는 안전한 안내와 재시도/종료 선택으로 보여 준다. 저장 실패 시 성공 화면으로 전환하지 않고 원본을 보존한다.
- 전환 직전 종료되어도 재시작 시 accepted 상태를 읽어 같은 inquiry를 보여 준다. 가설을 다시 생성하지 않는다.
- TUI 종료·예외·resize 후 입력/커서/터미널 상태를 복구해야 한다. 실행 중 다른 프로세스가 쓰기 잠금을 가진 경우에는 Busy를 안내하고 강제로 잠금을 해제하지 않는다.

## 구현 경계

UI는 FramingService/Commands를 호출하고 State를 표시한다. 파일에 직접 이벤트를 쓰거나 객체를 직접 수정하지 않는다. UI 전용 상태(현재 표시 질문, 페이지, 입력 초안)는 저장된 도메인 상태와 구분한다.

API 실행 중 Runner의 writer 잠금을 유지한다는 기존 계약을 고려한다. 화면 갱신 때문에 다른 Store reader로 잠금을 우회하지 않는다. 실행 상태 전달/렌더링 방식은 TUI 도구 실험과 구현 계획에서 정하고, 필요하면 코어 인터페이스 변경을 별도로 테스트한다.

새 TUI 의존성은 이 문서에서 선택하거나 설치하지 않는다. 기존 프로토타입은 표현 참고 자료이며 실제 라이브러리와 임의 DAG 레이아웃의 적합성 검증을 대신하지 않는다.

## 수용 기준

- [ ] ID 복사 없이 생각 입력 → 질문별 답변 → 제안 → 승인까지 진행한다.
- [ ] 답변 저장 후 종료, pending 제안 복원, 승인 저장 후 종료에서 중복 질문/모델 호출/가설이 없다.
- [ ] 키 없이 저장된 draft/accepted inquiry를 확인할 수 있다.
- [ ] 실패·거부·취소는 승인된 그래프를 만들거나 부분 변경하지 않는다.
- [ ] 실제 사용자 Framing 평가를 기록하고 Gate B의 별도 100노드/도구 평가를 마친다.
- [ ] Gate B 이후 실제 상태의 ID·부모·합류·종료 상태와 화면이 일치한다.
- [ ] 80/120/160열, 긴 한국어, 빈 지도, 페이지 경계, 터미널 resize/취소/종료를 검증한다.

대화형 진입의 자동 검증은 Gate B 통과의 증거가 아니다. 유료 API 테스트·새 의존성 설치·커밋·푸시는 이번 구현 작업에서 수행하지 않았다.
