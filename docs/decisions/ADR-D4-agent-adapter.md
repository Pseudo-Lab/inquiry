# ADR-D4 — Agent Adapter 계약

- 상태: **Accepted**
- 작성일: 2026-08-28
- 확정일: 2026-09-02
- 관련: PRODUCT-CONCEPT §10 §11 §16 §21.5 · REVIEW 1-④

## 맥락

원문은 "특정 모델·CLI에 종속되지 않는 실행 인터페이스"를 요구하지만 실제 계약이 없다. §10(진짜 heartbeat 있는 것만 애니메이션)과 §11(presence)이 성립하려면 어댑터가 스트리밍·비용·heartbeat를 표준화해야 한다.

## 결정

**모델 비종속 어댑터 인터페이스를 정의한다.** 어댑터는 아래 4가지를 표준 이벤트로 방출한다(D1 이벤트 로그와 동일 스트림에 흘림).

1. **실행 수명주기:** `started` → (`progress`)\* → `succeeded` | `failed` | `cancelled`.
2. **스트리밍 출력:** 부분 토큰/부분 결과를 `progress`로. 측정 불가한 사고 작업은 **퍼센트 금지**(§10) — 전체 작업량이 명확한 경우만 `{done, total}`.
3. **heartbeat:** 살아있는 실행만 주기적 `heartbeat` 방출. 끊기면 §11대로 `paused`/`connection-lost` 전이(애니메이션 중단).
4. **비용 회계:** 각 실행이 `{input_tokens, output_tokens, est_cost, model}`를 보고 → D6 예산 집계의 입력.

- **tool call:** 어댑터가 tool 호출을 표준 형태 `{name, args, result}`로 노출(모델별 포맷 차이는 어댑터가 흡수).
- **취소/경계:** 사람이 설정한 비용·시간·범위 경계(§4.4) 초과 시 어댑터가 실행을 `cancelled`로 중단.
- **첫 구현 대상:** Claude 계열(최신 모델). 어댑터 경계만 지키면 이후 다른 공급자 추가 가능.

## 근거

- heartbeat·비용·스트리밍을 어댑터 계약에 넣어야 §10·§11·D6가 전부 성립.
- 공급자 종속을 어댑터 한 겹으로 격리 → §19 비범위("특정 공급자 전용 구현 지양")와 정합.

## 결과 · 트레이드오프

- 어댑터마다 heartbeat·토큰 회계 매핑 구현 필요(신규 공급자 추가 비용).
- 측정 불가 작업의 "가짜 진행률 금지" 원칙 때문에 UI는 진행률 대신 활동 상태로 표현(§10).

## 열린 질문

- 로컬/오프라인 모델의 비용 회계(토큰만? 시간?) 표현 방식 → M3에서 결정.
