# ADR-D6 — 비용 모델

- 상태: **Accepted** (정책 확정; 기본 cap 수치는 M3 구현 시 실측 후 결정)
- 작성일: 2026-08-28
- 확정일: 2026-09-02
- 관련: PRODUCT-CONCEPT §4.4 §20(그래프 폭발) §19 · REVIEW 3-비용 · 의존: D4

## 맥락

여러 에이전트가 `fork`/`deepen`/`challenge`를 돌리면 토큰 비용이 폭발할 수 있다. 원문 §20이 "깊이·시간·비용 제한"을 한 줄 언급할 뿐, 비용 모델·예산 UI·spend cap이 전혀 설계돼 있지 않다. 에이전트 중심 도구에서 이는 신뢰·운영상 실질 위험.

## 결정

**inquiry별 예산(budget)과 spend cap을 1급 개념으로 둔다.** 회계 입력은 D4 어댑터의 비용 보고.

- **집계 단위:** inquiry 전체 / 개별 실행(agent run) 2단계로 누적 토큰·추정 비용 추적.
- **spend cap:** inquiry마다 상한(토큰 또는 비용) 설정. 상한 근접 시 경고, 초과 시 신규 에이전트 실행 차단(사람이 상향해야 재개) — §4.4 "사람이 경계를 가진다"의 구현.
- **경계 종류:** 비용 상한 + 탐색 깊이 상한 + 시간 상한(§20 그래프 폭발 대응)을 함께 제공.
- **표시:** TUI 상단 상태줄에 현재 inquiry의 누적 비용/예산을 노출(§9 상태 영역).
- **가짜 진행률 금지 원칙과 정합:** 비용은 실측값이므로 정확 표시 OK. 반면 사고 작업의 "진행률"은 표시 금지(§10, D4).

## 근거

- 에이전트 자율 실행에 사람이 설정한 예산 경계를 두는 것은 §4.4·§19("무제한 자율 실행" 비범위)의 직접 구현.
- D4가 실행별 비용을 보고하므로 집계·차단 로직만 추가하면 성립.

## 결과 · 트레이드오프

- 실행 전 비용 예측은 부정확할 수 있음 → 사후 누적 + 근접 경고 방식으로 보완.
- 로컬/오프라인 모델은 금전 비용이 없어 토큰·시간 기준으로 대체 표시(D4 열린 질문과 연결).

## 도입 시점

- **M0에서 정책 확정**, 실제 집계·차단 UI는 **M3(다중 에이전트)에서 구현**. M2(단일 사용자·수동 연산)에서는 최소한의 누적 표시만.
