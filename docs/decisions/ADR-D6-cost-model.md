# ADR-D6 — 비용 모델

- 상태: **Accepted** (정책 확정; 기본 cap 수치는 M3 구현 시 실측 후 결정)
- 작성일: 2026-08-28
- 확정일: 2026-09-02 · 보완: 2026-10-12 (M3 런타임 운용 결정 — 아래 섹션)
- 관련: PRODUCT-CONCEPT §4.4 §20(그래프 폭발) §19 · REVIEW 3-비용 · 의존: D4

## 맥락

여러 에이전트가 `fork`/`deepen`/`challenge`를 돌리면 토큰 비용이 폭발할 수 있다. 원문 §20이 "깊이·시간·비용 제한"을 한 줄 언급할 뿐, 비용 모델·예산 UI·spend cap이 전혀 설계돼 있지 않다. 에이전트 중심 도구에서 이는 신뢰·운영상 실질 위험.

## 결정

**inquiry별 예산(budget)과 spend cap을 1급 개념으로 둔다.** 회계 입력은 D4 어댑터의 비용 보고.

- **집계 단위:** inquiry 전체 / 개별 실행(agent run) 2단계로 누적 토큰·추정 비용 추적.
- **spend cap:** inquiry마다 상한(토큰 또는 비용) 설정. 상한 근접 시 경고, 초과 시 신규 에이전트 실행 차단(사람이 상향해야 재개) — §4.4 "사람이 경계를 가진다"의 구현.
- **경계 종류:** 비용 상한 + 탐색 깊이 상한 + 시간 상한(§20 그래프 폭발 대응)을 함께 제공.
- **표시:** TUI 상단 상태줄에 현재 inquiry의 누적 비용/예산을 노출(§9 상태 영역).
- **가짜 진행률 금지 원칙과 정합:** 비용은 실측값이므로 정확 표시 OK. 반면 사고 작업의 "진행률"은 표시 금지(§10, D4).

## M3 런타임 운용 결정 (2026-10-12)

정책(위)은 그대로 두고, M3에서 런타임으로 구현하며 확정한 운용 수준 결정. [구현 계획](../superpowers/plans/2026-10-12-m3-d6-spend-cap.md) 참조.

- **메트릭 = 토큰(v0).** `openai_adapter`가 `est_cost`를 채우지 않아(항상 None) 금액 cap은 불가. `Runner`가 집계하는 input+output 토큰으로 cap. 금액 cap은 모델별 가격표 연동 후 후속.
- **opt-in 기본.** cap 미설정이면 무제한. `inquiry budget set --max-tokens N`으로 켠다. 적정 기본값은 M3 실측 후(열린 질문).
- **soft cap(사후 누적).** 누적 known 토큰 ≥ cap이면 **신규 run 차단**. 진행 중 run 비용은 예측 차감 안 함(overshoot 최대 run 1회).
- **차단 지점 = `Runner.execute` 공통 지점 1곳.** 모든 agent run(framing·branch·operation·assessment)이 거치는 사전검사에서 판정 → 서비스별 중복 없음. 차단은 `ValueError`로 전파, 사람이 `budget set`으로 상향 시 재개. `recover()`는 execute 미경유라 cap 무관.
- **cap 설정은 inquiry 존재 시에만**(human 액터). framing 단계(inquiry 생성 전)는 cap 미적용(cost bounded).
- **근접 경고.** run 성공 후 누적이 cap의 임계(기본 90%) 이상이면 CLI가 stderr 경고(사후 누적 보완책).
- **표시.** `inquiry budget show`로 누적/cap/잔여/over/near 조회. TUI 상태줄 노출은 표현계층(후속).
- **범위.** 이번 슬라이스는 **토큰 cost cap만**. 경계 3종 중 깊이 상한·시간 상한(run timeout 외)은 후속(현 코드 없음).

## 근거

- 에이전트 자율 실행에 사람이 설정한 예산 경계를 두는 것은 §4.4·§19("무제한 자율 실행" 비범위)의 직접 구현.
- D4가 실행별 비용을 보고하므로 집계·차단 로직만 추가하면 성립.

## 결과 · 트레이드오프

- 실행 전 비용 예측은 부정확할 수 있음 → 사후 누적 + 근접 경고 방식으로 보완.
- 로컬/오프라인 모델은 금전 비용이 없어 토큰·시간 기준으로 대체 표시(D4 열린 질문과 연결).

## 열린 질문

- **기본 cap 수치.** opt-in이라 미설정이 기본이나, 권장 기본값(토큰)을 M3 실측 후 제시할지.
- **near 경고 정확 임계.** v0 90% 고정. 실측 후 조정 여부.
- **금액(cost) cap.** openai_adapter의 `est_cost`/`price_ref`를 가격표로 채운 뒤 금액 기준 cap 추가.
- **깊이·시간 상한.** ADR이 언급한 3종 경계 중 비용 외 2종의 구현 시점.

## 도입 시점

- **M0에서 정책 확정**, 실제 집계·차단은 **M3에서 구현(2026-10-12 토큰 cap·CLI 완료)**. 깊이/시간 상한·금액 cap·TUI 표시는 후속.
