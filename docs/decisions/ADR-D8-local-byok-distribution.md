# ADR-D8 — 서버 운영 없는 로컬 오픈소스·BYOK 배포

- 상태: **Accepted**
- 작성일: 2026-09-20
- 확정일: 2026-09-20
- 관련: PRODUCT-CONCEPT §4.7 §19 · 의존: D1, D4, D6

## 맥락

PRODUCT-CONCEPT §4.7의 로컬 우선과 §19의 공급자 비종속 원칙은 정해져 있으나, 모델 호출 비용과 서비스 운영의 주체는 명시하지 않았다. 프로젝트 소유자는 서비스를 직접 운영하지 않고 오픈소스로 공개하여 사용자가 설치·사용하는 방식을 선택했다.

## 결정

- 기본 배포 방식은 사용자 컴퓨터에서 실행하는 독립 CLI다. 프로젝트 운영자의 로그인 서버·모델 호출 중계 서버·공유 API 키를 요구하지 않는다.
- 모델 기능은 BYOK(Bring Your Own Key)다. 사용자가 자신의 공급자 계정과 API 키를 설정하고 CLI가 선택한 공급자를 직접 호출한다. 사용료는 사용자가 해당 공급자에 직접 지불한다.
- 첫 공급자는 OpenAI이며 필수적인 영구 종속성은 아니다. D4의 어댑터 경계를 유지하고 다른 공급자·로컬 모델은 후속 확장으로 둔다. 현재 지원된다고 표시하지 않는다.
- Codex/Claude CLI의 설치나 구독을 기본 사용 조건으로 요구하지 않는다. 이들이 Inquiry CLI를 도구로 사용하는 연동은 선택적 후속 기능이다.
- 기록과 산출물은 로컬에 보존한다. 저장·조회·복원·사람 승인 같은 비모델 기능은 키나 네트워크 없이 동작한다.
- 로컬 저장이 외부 전송 없음을 뜻하지는 않는다. 모델 실행 시 seed·관련 Q&A·가설 등 필요한 문맥이 선택한 공급자에 전송된다는 점과 API 사용료를 설정 안내와 실행 경계에 명시한다. 불필요한 프로젝트 파일을 자동 전송하지 않는다.
- 키는 이벤트·출력·오류 로그·export·Git에 포함하지 않는다. 프로젝트 범위 설정을 지원하고 shell export를 필수로 요구하지 않는다. 구체적인 안전한 저장 방식과 설정 UX는 M2-4에서 설계·검증한다.

## 근거 (provenance)

- 2026-09-20 프로젝트 소유자 대화: “운영하지 않고, 오픈소스로 공개해서 사용자가 알아서 사용”하기를 요청했고, 로컬 CLI + 사용자 API 키 제안에 “이 방법으로 하자”라고 확정했다. 이는 사람의 제품 방향 결정이며 시장 검증 결과는 아니다.
- PRODUCT-CONCEPT §4.7: 로컬 우선과 개방형 기록. §19: 특정 모델 공급자 전용 구현 제외.
- ADR-D4: 공급자 독립 어댑터, 첫 OpenAI 구현. ADR-D6: 실제 사용량과 미확인 비용의 구분.

## 결과 · 트레이드오프

운영자가 모델 중계·사용자 과금 서버를 유지하지 않아도 된다. 대신 사용자는 공급자 계정·키·사용료를 관리해야 하며, 설치·초기 설정·오류 안내 문서가 중요하다. 오픈소스라는 이유로 외부 모델 호출이 무료이거나 오프라인이 되는 것은 아니다. 키 보관과 공급자 전송 범위를 명확히 안내해야 한다.

## 대안 (기각)

- 운영자 제공 로그인·중계·통합 과금: 서비스 운영을 하지 않겠다는 현재 방향과 충돌하므로 기본 계획에서 제외한다.
- Codex/Claude CLI 필수 의존: 별도 도구 설치·계정 조건을 사용자에게 강제하므로 기본 경로에서 제외한다. 선택 연동 가능성은 유지한다.
- OpenAI 전용 코어: 공급자 비종속 원칙에 어긋나므로 기각한다. 최초 어댑터만 OpenAI로 구현한다.

## 열린 질문

- M2-4 구현 전: 프로젝트 범위 키 설정의 저장 위치·권한·우선순위·Git 제외 및 안전한 오류 처리 방식을 확정한다. 저장 방식이 정해지기 전 설정 기능을 구현 완료로 표시하지 않는다.
- 공개 배포 전: 설치 패키징·배포 채널·라이선스와 최초 설정 안내를 점검한다. 이 ADR만으로 배포 준비가 완료된 것은 아니다.
- 후속 마일스톤: 다른 공급자·로컬 모델·에이전트 도구 연동의 우선순위를 정한다. 기존 팀 기능 계획도 운영자 호스팅을 전제로 하지 않으며, M4에서 배포·인증 방식을 별도로 결정한다.
