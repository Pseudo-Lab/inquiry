# ADR-D9 — 대화형 Framing 후 승인 시 Git-log 화면으로 전환

- 상태: **Accepted**
- 작성일: 2026-09-20
- 확정일: 2026-09-20
- 관련: PRODUCT-CONCEPT §7·§9·§18 · 의존: D7, D8

## 맥락

테스트용 CLI는 긴 세션/질문 ID 복사와 JSON 읽기가 필요하다. 사용자가 실행법을 이해하기 어렵다고 지적하며 대화형 화면과 선택한 Git-log 화면의 연결을 요청했다.

## 결정

Framing 중에는 대화에 집중하고, 프레임/후보에 대한 사람 승인을 저장한 뒤 Git-log 화면으로 전환한다. 시작부터 빈 지도와 대화를 동시에 표시하지 않는다. 실제 가설만 보여 주며 생성·승인·복구의 기존 코어 계약을 재사용한다.

D7의 Gate B는 유지한다. 대화형 순차 입력을 먼저 구현·검증하고, 실제 Git-log TUI 통합은 Gate B 확인 후 진행한다. 클릭/방향키 상세 탐색과 미구현 AI 탐구 연산을 이번 결정으로 앞당기지 않는다.

## 근거 (provenance)

2026-09-20 사용자가 “대화형 화면과 git-log tui까지 연결해볼까?”라고 요청했다. 대화 먼저/승인 후 전환과 처음부터 동시 표시의 두 안을 제시했고, 추천한 전환 방식에 “좋아. 그 방식이 좋겠어”라고 직접 승인했다. 이는 화면 흐름의 선택이며 사용성 검증 완료 판단은 아니다.

## 결과 · 트레이드오프

초기 입력 단계가 단순해지고 빈 지도 영역을 읽을 필요가 없어진다. 대신 승인 후 화면 전환과 재시작 시 진입 위치를 명확히 처리해야 한다. 상세 입력/실패 처리와 수용 기준은 [설계 문서](../superpowers/specs/2026-09-20-conversation-gitlog-design.md)에서 검토한다.

## 대안 (기각)

- 처음부터 대화와 지도 동시 표시: 승인 전에는 지도가 비어 있고 첫 사용 단계가 복잡해져 기본 흐름에서 제외한다.
- 현재 단발 명령만 유지: ID 복사와 JSON 해석의 사용 부담을 해결하지 못하므로 기본 대화 흐름을 추가한다. 기존 명령 자체는 호환성을 위해 유지한다.

## 열린 질문

대화형 진입 명령은 후속 구현에서 `chat`으로 확정했다. Gate B에서 TUI 도구와 실제 터미널 적합성, 지속형 화면의 실행 상태 전달 인터페이스를 확인한다. 이 결정은 특정 라이브러리 추가나 Gate B 통과를 승인한 것이 아니다.
