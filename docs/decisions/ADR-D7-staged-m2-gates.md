# ADR-D7 — M2 코어 개발과 UX 검증의 단계별 게이트

- 상태: **Accepted**
- 작성일: 2026-09-17
- 확정일: 2026-09-17
- 관련: PRODUCT-CONCEPT §7·§9·§18·§22 · REVIEW 부록 C · 의존: D1~D6

## 맥락

M1a의 최초 사용 UX와 M1b의 100노드 페이지 탐색은 미검증으로 남아 있다. 기존 마일스톤은 M1a/M1b 전체 통과를 모든 M2 구현의 전제로 두지만, 저장·복원 코어는 TUI 통합과 분리해 검증할 수 있다.

## 결정

저장·복원 코어 개발과 잔여 UX 검증을 병행한다. UX 검증을 생략하거나 M1a/M1b를 자동 통과로 바꾸지는 않는다.

- **Gate A — 코어 착수:** D1~D6와 검토된 구현 계약을 기준으로 저장·복원부터 시작한다. 잔여 UX와 TUI 도구 선정은 이 첫 구현을 막지 않는다.
- **Gate B — TUI 통합 전:** M1a 최초 프레이밍 UX, M1b 페이지 탐색의 가독성·접근성, 선택된 시각 규칙과 TUI 도구를 확인·기록한다. 이 조건이 해소되기 전 M2-6 TUI 통합은 시작하지 않는다.
- 코어 작업은 기존 계획 범위로 한정한다. 클릭/키보드 노드 상세 탐색의 MVP 이후 일정과 D1~D6의 도메인 계약은 바꾸지 않는다.

## 근거 (provenance)

2026-09-17 사용자 직접 선택: “저장·복원 코어 개발과 병행하고 TUI 통합 전 마무리 (추천)”. 이는 진행 순서에 대한 사람의 결정이며, UX 품질이 검증됐다는 근거가 아니다.

기존 미검증 범위는 [M1a 마감 보고서](../reports/m1a-closeout.md)와 [M1b 규모 보고서](../reports/m1b-scale-eval.md)에 기록되어 있다.

## 결과 · 트레이드오프

저장 코어를 먼저 검증할 수 있으나, 나중의 UX 결과에 따라 UI와 일부 명령 흐름이 달라질 수 있다. 코어와 TUI를 분리하고 [M2 진입 기록](../reports/m2-entry-check.md)에서 두 게이트를 각각 관리한다.

## 대안 (기각)

모든 UX 검증이 끝날 때까지 M2 전체를 중단하는 순서는 사용자가 선택하지 않았다. UX 검증을 삭제하거나 전면 통과로 처리하는 방식도 선택하지 않았다.

## 열린 질문

Gate B에서 최초 사용 UX와 100노드 탐색의 잔여 검증을 완료한다. 구체적인 통과 관찰과 TUI 도구 선택은 M2-0B에서 기록한다. 이 결정은 그 결과를 미리 확정하지 않는다.
